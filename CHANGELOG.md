# Changelog

## [0.2.0] — 2026-08-27 — live mode's commit-time triggers

- Added live mode: `spar live-hook`, a UserPromptSubmit hook that plants one conceptual/architectural/procedural error directly into a real chat reply, plus `spar live-reveal` to close out the trial once the model asks the user whether they caught it. Off by default (`SPAR_LIVE_ENABLED`), opt-in per project via `.claude/settings.local.json`, never sandboxed the way `spar review` is — a planted claim lives in a real conversation before it's caught. See README's "Live mode" section.
- Added `spar live-induce`: a one-shot marker that forces the next `spar live-hook` invocation to plant regardless of cooldown, for testing and dogfooding live mode without waiting out `SPAR_LIVE_COOLDOWN`. No effect on a session with a plant already pending reveal.
- Added `spar stats --trend`: catch rate broken out by week and by injected category, across both modes. Previously spar had no way to answer whether catch rate was actually moving, or whether the same category kept getting missed — the open question docs/DESIGN.md named against Frey's obsolescence litmus test.
- Live mode's reveal now splits across two separate turns instead of one: the hook emits only the "did anything seem off" question on the first eligible turn, and only emits the disclose-and-log instructions — including the `spar live-reveal` Bash call, whose arguments name what was planted — once a full separate user turn has passed (tracked by a new `Pending.Asked` flag). Previously both were emitted together on every eligible turn, trusting the model to sequence them across turns on its own; a model that asked and disclosed in the same reply would compose the `live-reveal` call, description visible in the tool call, before a genuine answer existed to disclose against. The split also now names the non-answer case explicitly: if the user's next message doesn't actually answer the question, log it as an implicit `--caught no` rather than blocking on an answer that isn't coming.
- Added a default "silent" reveal mode for live mode, replacing the ask-then-wait flow above as the default (still available via `SPAR_LIVE_REVEAL_MODE=ask`). Asking "did anything seem off" turned out to hand the reviewer a fresh, explicit invitation to go re-examine the planted reply — a different signal than whether they noticed it during ordinary reading, confirmed live by a reviewer who reported compulsively re-checking every time the question fired. Silent mode classifies the outcome from the reviewer's own prior behavior instead, with a new `unengaged` outcome (and `store.OutcomeUnengaged`) for the honest case where nothing in that behavior bears on the planted claim either way — kept out of catch-rate math rather than folded into a fabricated miss.
- Added a stats nudge for live mode: at most once a day (`SPAR_LIVE_STATS_INTERVAL`, default 24h, `0` disables), spar has the model mention the current catch rate as a passing aside and point to `spar stats --trend` for the rest, rather than reproducing the breakdown inline. Global across projects, not per session, and never fires on the same turn as a reveal. The number is computed by the hook itself from the log, not left to the model to recall or guess.
- The trial log now keeps the injected bug's description (`injected_description`), not just its category and severity — a miss was previously only inspectable in the terminal at the moment it happened, then gone.
- The category taxonomy now branches by content kind: a parallel prose taxonomy (flipped recommendations, misattributed tradeoffs, unsupported claims, and so on) covers markdown/plaintext files like ADRs and design docs, alongside the existing code taxonomy. Verified end-to-end against a real ADR diff.
- A validated mutation that lands outside the allowed line range now gets one retry at the same candidate before falling back to clean, instead of giving up immediately — found live-testing the taxonomy change above, where a multi-region prose edit's hunk gaps made this a real, not just theoretical, failure mode.
- Live mode's reveal now always restates the correct fact plainly, in both reveal modes, instead of only naming that something was wrong. The planted claim is a permanent part of Claude Code's own transcript on disk — a real reply, persisted the same as any other — and `spar live-hook` never edits that file itself (it only ever reads it, for corroboration), so until now the reveal turn was the sole place the truth could be restated for a reader who later finds it out of context.
- Added `spar live-fixup`: a manual, opt-in command that patches a live-mode plant's corrected fact directly into a closed session transcript — the one exception to the line above, and a deliberately different shape of risk from anything automatic: one named `--session` at a time, never triggered by a hook, refuses if the transcript looks recently modified (soft guard, `--force` to override), backs up the whole file before writing, and only ever replaces text found as an exact, single, unambiguous match inside a genuine assistant reply. What counts as the plant's real wording is verified byte-for-byte against the live transcript at reveal time (new `--original-text`/`--corrected-text` flags on `spar live-reveal`, checked against a newly-captured `Pending.PlantText`), never trusted on the model's memory alone. See README's "Live mode" section.
- Added `spar live-hook-commit`: a `PreToolUse` hook, gated on `git commit` Bash calls, that gives `spar review`'s "you have to remember to run it" problem the same fix live mode already gave chat replies — the model narrates a commit it's about to make with one subtly wrong fact, never touching the commit's real content. Reuses live mode's existing plant/reveal state machine and taxonomy pattern entirely: shares the chat-triggered hook's cooldown and pending-plant slot rather than adding a second deception budget, reveals through the same `spar live-reveal` flow, and adds two new taxonomy categories (`misdescribed-change-scope`, `misattributed-commit-motivation`) to the existing pool rather than a commit-only sub-list. `spar review` itself, and the API-mutation pipeline behind it, are untouched — this is a third, additive mechanism, not a replacement. Guards in code against the `if` filter's documented fail-open behavior on `$()`/backtick/`$VAR` commands, on top of an instruction-level bail-out if the matched command turns out not to have been a real commit. See README's "Live mode" section.
- Added `SPAR_LIVE_COMMIT_MODE` (`narrate` | `notify` | `gate`, default `narrate`) to `spar live-hook-commit`: `notify` folds a REAL `internal/inject` diff mutation into live mode's existing plant/reveal machinery instead of a model-fabricated verbal claim, bounded to a hook-safe latency via new `inject.HookConfig()` (one HTTP attempt, 8s timeout, no validation retry — spar review's own `DefaultConfig()` values are unchanged, this is a new call site only) — shares narrate's cooldown/pending slot, reveals through the same `spar live-reveal` flow, and now auto-fills `InjectedFile`/`InjectedSeverity`/`InjectedDescription`/`DiffHash` from spar's own exact ground truth (new `Pending`/`Trial` fields, plus `Trial.LiveKind` to distinguish which taxonomy a live trial's category came from) rather than trusting the model's memory the way narration always has. `gate` is a pure friction checkpoint, deliberately decoupled from all of the above: shows the real, unmutated diff via `permissionDecision:"ask"` and forces a pause before the commit lands, never injects (a one-shot ask/deny prompt has no way to disclose a blind mutation afterward, unlike every other spar mechanism), never scores, never touches `internal/livestate` at all. `.claude/settings.local.json`'s commit-hook `timeout` moves from `10` to `15` to give `notify` mode's bounded network call headroom. See README's "A commit-time trigger" section.

## [0.1.1] — 2026-08-25 — spar doctor

- Added `spar doctor`: checks whether a key resolves and from which of the three sources, whether `git` and `delta` are on `PATH`, and whether the log directory is writable. No install/uninstall subcommands — spar has no Claude Code config to wire up or unwind, unlike the sibling tools that pattern comes from.
- Split an overloaded sentence in README's "How it works" (step 3 was doing three jobs at once) after a readability-focused cold read flagged it.

## [0.1.0] — 2026-08-25 — initial release

`spar review` (diff capture, coin-flip injection, LLM-driven mutation scoped to real changed hunks, local diff regeneration, delta rendering, catch/miss/false-positive/true-negative logging) and `spar stats`. No scoring or live-embedded hook — see [docs/DESIGN.md](docs/DESIGN.md) for what v1 deliberately leaves out and why.

- The added-file diff header matches real git byte-for-byte (an earlier draft was missing `new file mode` and showed the wrong `---` line).
- The temp-scratch path fails closed on a non-absolute `$TMPDIR`, avoiding a write inside the working tree.
- The file-size cap runs right after a candidate's content is read, ahead of the API call.
- `SECURITY.md` accurately describes when a file's content leaves the machine.
- `internal/gitdiff` and `internal/inject`'s git-shelling functions are tested against real scratch repos — 43% → 91% and 17% → 65% coverage — including a permanent regression test for the added-file header fix above.
